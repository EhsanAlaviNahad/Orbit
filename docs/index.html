What you can do from the keyboard

Orbit scans only the focused window, using macOS Accessibility for native controls and optional on-device Vision OCR where the accessibility tree is sparse.

Click, double-click, right-clickReturn, Option-Return, Shift-Return
Arrange the windowleft, right, top, bottom, center, fill, maximize, full screen
Scroll with hints openOption-Up / Option-Down, 0.5× to 3×
System commandsrestart, shutdown, sleep — each needs two Returns

Try the search here

This is a simulator running in your browser, not Orbit itself. Its search is a line-by-line port of TargetSearch from Core.swift — same normalisation, same five ranking tiers, same command aliases, and the same exact-only rule for the system commands — verified against the Swift implementation across 22 queries. It searches a fixed list of controls and commands, so the hint labels are illustrative rather than a live scan: Orbit needs a real macOS window to read.

Install

curl -fsSL https://raw.githubusercontent.com/EhsanAlaviNahad/Orbit/main/Scripts/install.sh | bash

Requires an Apple silicon Mac on macOS 27 or newer, plus the Swift 6.2 command line tools. Orbit then lives only in the menu bar; grant it Accessibility on first use. The script replaces ~/Applications/Orbit.app and removes ~/Applications/Eclick.app only if that bundle carries Orbit's old identifier — read Scripts/install-app.sh, which is where that happens, before you pipe it into a shell.

Privacy

No network calls, no telemetry, no accounts. Screen content, element names, and everything you type stay in memory on your Mac. OCR runs on-device through Vision.
